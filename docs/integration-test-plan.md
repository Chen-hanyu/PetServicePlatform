# 前后端联调执行计划

本文档用于指导宠物综合服务平台前后端联调。联调人员应按步骤执行测试，并在文末表格中记录结果、问题和处理状态。

## 1. 联调目标

- 验证用户 Web 前台、管理员后台与 Spring Boot 后端接口链路可用。
- 验证认证、权限、分页、筛选、业务状态流转和异常提示符合预期。
- 验证前台提交的数据能在后台被审核或处理，后台变更能回到前台可见。
- 发现接口字段、状态值、权限、数据初始化和页面交互问题，并形成可追踪记录。

## 2. 环境准备

### 2.1 基础依赖

| 项目 | 要求 |
|------|------|
| JDK | Java 17 或更高，建议使用项目当前可运行版本 |
| Node.js | 支持 Vite 6 的 Node.js 版本 |
| 数据库 | MySQL 8.x |
| 后端端口 | `8080` |
| 前端端口 | `5173` |
| API 前缀 | 用户端 `/api/v1`，管理端 `/api/v1/admin` |

### 2.2 数据库初始化

方式一：使用 Docker Compose。

```bash
docker compose up -d mysql
```

方式二：使用本机 MySQL。

```sql
SOURCE backend/src/main/resources/sql/schema.sql;
SOURCE backend/src/main/resources/sql/seed.sql;
```

注意：`seed.sql` 会清理并重建演示数据，只用于本地联调和演示环境，不要在生产库执行。

如果接口响应本身已经出现中文乱码，例如 `/api/v1/community/posts` 返回的标题是 `å® ç‰©...`，说明数据库中已经写入了错误编码的数据。请重新执行 `schema.sql` 和 `seed.sql` 初始化数据库；脚本已包含 `SET NAMES utf8mb4`，用于保证 SQL 客户端按 UTF-8 解析中文。

Docker 环境推荐在 MySQL 容器内直接读取挂载脚本，避免 Windows PowerShell 管道转换中文编码：

```bash
docker exec pet-platform-mysql sh -c "mysql -uroot -p123456 --default-character-set=utf8mb4 < /docker-entrypoint-initdb.d/01-schema.sql && mysql -uroot -p123456 --default-character-set=utf8mb4 < /docker-entrypoint-initdb.d/02-seed.sql"
```

不要使用 `Get-Content ... | docker exec mysql ...` 导入中文 SQL，PowerShell 管道可能把 UTF-8 中文转换成 `?` 或写入双重编码数据。

### 2.3 启动服务

后端：

```bash
cd backend
.\mvnw.cmd spring-boot:run
```

前端：

```bash
cd frontend
npm run dev
```

| 检查项 | 期望结果 |

## 4. 联调执行顺序

### 4.1 基础链路

| 步骤 | 操作 | 期望结果 |
|------|------|----------|
| 1 | 打开用户首页 `/home` | 首页 Banner、推荐内容、商品和服务数据正常展示 |
| 2 | 打开社区列表 `/community` | 展示已审核帖子，分页和分类筛选可用 |
| 3 | 打开商品页 `/shop` | 商品分类、商品列表和详情可用 |
| 4 | 打开服务页 `/services` | 服务分类、商家列表和商家详情可用 |
| 5 | 打开领养页 `/adoption` | 领养宠物列表、详情和流程说明可用 |

### 4.2 用户认证与权限

| 步骤 | 操作 | 期望结果 |
|------|------|----------|
| 1 | 使用普通用户登录 | 登录成功，`localStorage` 写入 `pet_platform_token` |
| 2 | 刷新页面后访问 `/profile` | 登录态保持，个人中心接口正常返回 |
| 3 | 未登录访问 `/profile` | 跳转到 `/login` |
| 4 | 普通用户访问 `/admin/dashboard` | 被前端路由拦截并回到用户端页面 |
| 5 | 管理员登录 `/admin/login` | 登录成功并进入 `/admin/dashboard` |
| 6 | 未登录直接请求后台接口 | 后端返回 401 |
| 7 | 普通用户 token 请求后台接口 | 后端返回 403 |

### 4.3 社区闭环

| 步骤 | 操作 | 期望结果 |
|------|------|----------|
| 1 | 用户发布帖子 | 新帖子状态为 `PENDING`，前台公开列表暂不展示 |
| 2 | 管理员进入内容管理 | 能看到待审核帖子 |
| 3 | 管理员审核通过帖子 | 帖子状态变为 `APPROVED` |
| 4 | 回到前台社区列表 | 审核通过的帖子可见 |
| 5 | 用户评论、点赞、收藏帖子 | 数量和状态变化符合预期 |
| 6 | 进入我的收藏 | 收藏列表展示对应帖子，取消收藏后列表更新 |

### 4.4 商城闭环

| 步骤 | 操作 | 期望结果 |
|------|------|----------|
| 1 | 用户进入商品详情 | 商品详情、价格、库存正常展示 |
| 2 | 加入购物车 | 购物车数量和总价更新 |
| 3 | 修改购物车数量 | 数量和金额重新计算 |
| 4 | 提交订单 | 生成订单，状态进入待处理或待支付状态 |
| 5 | 用户进入我的订单 | 能看到新订单 |
| 6 | 管理员进入订单管理 | 能搜索或筛选该订单 |
| 7 | 管理员更新订单状态 | 前台订单状态同步变化 |

### 4.5 服务预约闭环

| 步骤 | 操作 | 期望结果 |
|------|------|----------|
| 1 | 用户选择商家和服务项目 | 商家详情中服务项目可选 |

### 4.6 领养闭环

| 步骤 | 操作 | 期望结果 |

| 步骤 | 操作 | 期望结果 |

| 4 | 服务管理新增或编辑商家服务 | 服务列表和商家详情同步变化 |

### 4.9 AI 与文件上传

| 步骤 | 操作 | 期望结果 |
|------|------|----------|
| 1 | 调用 AI 宠医助手 | 配置 API Key 时返回回答和建议 |
| 2 | 移除或置空 AI Key 后调用 | 返回友好的未配置提示，不影响其他功能 |
| 3 | 上传合法图片文件 | 返回可访问的文件 URL |
| 4 | 上传超大或非法文件 | 返回明确错误提示 |

## 5. 异常与边界测试

| 场景 | 操作 | 期望结果 |
|------|------|----------|
| Token 过期或缺失 | 清空 `localStorage` 后访问个人中心 | 前端跳转登录，后端返回 401 |
| 后台权限隔离 | 普通用户 token 请求 `/api/v1/admin/users` | 返回 403 |
| 分页边界 | 请求第一页、第二页和空页 | `list`、`total`、`page`、`page_size` 正确 |
| 重复领养申请 | 同一用户重复申请同一宠物 | 返回业务错误 |
| 预约时间冲突 | 同一服务同一时间重复预约 | 返回业务错误 |
| 库存不足 | 下单数量超过库存 | 返回业务错误 |
| 数据为空 | 使用无结果筛选条件 | 页面展示空状态，不报错 |
| 后端异常 | 临时停止后端再操作页面 | 前端展示网络错误或失败提示 |

## 6. 问题记录规则

- 每个问题必须记录复现步骤、请求路径、请求参数、响应结果和截图或日志。
- 接口字段问题优先标注前端期望字段和后端实际字段。
- 权限问题必须记录当前账号、角色、token 是否存在和接口响应状态码。
- 数据问题必须记录数据来源，是初始化数据、页面新增数据还是后台修改数据。
- 已修复问题需要回归原步骤，并在联调表中补充回归结果。
