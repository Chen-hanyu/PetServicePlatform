# 前后端联调方案与现状对齐（2026-04-15）

## 1. 前后端对接原则（以“后端文档 + 后端代码”为准）

鉴于当前“前端文档落后于代码、后端文档与代码同步”，联调时建议按以下优先级执行：

1. **第一真相源：后端路由与安全配置代码**
2. **第二真相源：`docs/api.md` 与 `docs/backend-status.md`**
3. **前端仅作为调用方实现，发现不一致即回归后端契约修正前端**

## 2. 建议联调步骤（可直接执行）

### 步骤 A：冻结联调契约
- 从后端控制器汇总接口路径（用户端 `/api/v1/*`，管理端 `/api/v1/admin/*`）。
- 以 `ApiResponse<{...}>` 和分页结构 `{ list, total, page, page_size }` 作为统一返回契约。

### 步骤 B：前端 API 层一一映射
- 统一通过 `frontend/src/api/http.ts` 的 `webHttp` 与 `adminHttp` 发起请求。
- 所有模块 API 均放在 `frontend/src/api/modules/*.ts`，禁止在页面内硬编码 URL。
- 页面只消费 `modules` 导出函数，不直接拼接接口。

### 步骤 C：鉴权与角色联调
- 登录后把 `token + user(role)` 写入 `auth` store。
- axios 请求拦截器统一挂载 `Authorization: Bearer <token>`。
- 路由守卫按 `requiresAuth` + `role` 执行用户/管理员隔离。

### 步骤 D：按业务主链路串联联调
1. 认证（用户 / 管理员登录）
2. 首页聚合、社区列表/详情
3. 社区写操作（发帖、评论、点赞）
4. 领养（列表、详情、申请）
5. 服务（分类、商家、预约）
6. 商城（商品、购物车、下单）
7. 个人中心（overview、宠物档案、消息）
8. 管理端（dashboard、用户、帖子审核）

### 步骤 E：联调验收基线
- 正向：接口成功返回 `code = 0`，页面渲染正常。
- 逆向：401 时前端自动登出；管理员路径非 ADMIN 角色拒绝访问。
- 分页：列表接口必须验证 `page/page_size/total/list`。

## 3. 已识别差异（前端文档 vs 实际代码）

### 3.1 请求层目录命名不一致
- 文档写的是 `src/services/`。
- 实际代码是 `src/api/http.ts + src/api/modules/*.ts`。

### 3.2 管理端功能描述超前于当前页面实现
- 文档描述后台“服务管理、商城管理”已覆盖完整管理能力。
- 代码中 `ServicesAdminPage.vue`、`ShopAdminPage.vue` 仍是“待接入接口”的占位页。

### 3.3 前端运行文档对目录说明滞后
- 文档/README 中建议结构仍强调 `services/`。
- 实际目录已形成 `api/` 分层（`http.ts + modules`），并且已被页面广泛引用。

### 3.4 前端存在“接口失败回退本地 mock”模式（联调需显式关闭或标记）
- 例如首页接口失败会回退 `mockHomeData`，这会在联调阶段掩盖后端真实错误。
