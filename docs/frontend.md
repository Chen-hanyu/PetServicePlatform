# 前端模块说明（宠物综合服务平台）

## 1. 模块功能
前端改为 Web 端实现，负责落地用户前台和管理员后台两套界面，统一承接设计说明与信息架构中的页面、交互和视觉规范。

前端分为两部分：
- 用户 Web 前台：面向普通用户，提供首页、社区、领养、宠物服务、商城、个人中心等功能。
- 管理员后台：面向运营和审核人员，提供用户管理、帖子审核、领养审核、商家与服务管理、商品管理、订单管理、内容推荐位管理等功能。

用户 Web 前台覆盖业务如下：
- 首页：顶部导航、搜索区、Banner、快捷入口、推荐内容、推荐服务、推荐商品、今日宠物小贴士、随机萌宠卡片。
- 社区：推荐/最新切换、内容分类筛选、帖子卡片流、帖子详情、评论区、发布帖子。
- 领养：领养说明、待领养宠物列表、宠物详情、领养申请表单、领养流程入口。
- 宠物服务：服务分类入口、商家列表、商家详情、预约表单、附近服务推荐。
- 商城：商品分类、商品列表、商品详情、购物车、订单提交流程。
- 个人中心：个人信息、我的宠物、宠物档案、我的内容、我的订单、我的领养、消息中心、宠物成长时间轴。

管理员后台覆盖业务如下：
- 仪表盘：核心数据统计、待处理事项、最近操作记录。
- 用户管理：用户资料、账号状态、消息通知。
- 内容管理：帖子列表、帖子审核、评论管理、标签管理、Banner 与推荐位管理。
- 领养管理：待领养宠物信息维护、领养申请审核、领养流程配置。
- 服务管理：商家管理、服务分类、服务项目、预约单处理。
- 商城管理：商品分类、商品上下架、库存、订单处理、折扣专区配置。

## 2. 技术选型
- 框架：Vue 3
- 构建工具：Vite
- 语言：TypeScript
- 路由：Vue Router
- 状态管理：Pinia
- 网络请求：Axios
- 样式方案：SCSS + Design Token
- UI 方案：前台使用自定义业务组件，后台使用表格与表单型管理组件

技术实现原则：
- 用户前台和管理员后台共用一套基础主题变量、请求层和通用组件规范。
- 前台强调卡片式布局、轻动效和品牌风格，后台强调信息密度、表格效率和操作清晰度。
- 路由、权限、菜单、按钮级操作能力按角色拆分，保证 `user` 和 `admin` 两类身份访问隔离。

## 4. 运行方式
1. 进入前端目录：`cd frontend`
2. 安装依赖：`npm install`
3. 启动开发环境：`npm run dev`
4. 生产构建：`npm run build`
5. 本地预览构建结果：`npm run preview`

## 5. 设计落地要求
- 用户前台遵循“温暖治愈、日系软萌”的视觉风格，使用浅色背景、圆角卡片、轻量动效。
- 管理员后台以清晰、高效、可批量处理为目标，降低装饰性，强化表格、筛选、状态标签与操作反馈。
- 前后台都通过 Design Token 统一颜色、字体、圆角、阴影和状态色。
- 前台突出体验完整度，后台突出业务闭环和管理效率。

## 6. 联调范围
- 用户端：登录、首页聚合、社区、领养、服务预约、商城交易、宠物档案、个人中心。
- 管理端：登录、仪表盘、用户管理、帖子审核、领养审核、商家与服务管理、商品管理、订单处理、推荐位管理。

## 7. 前后端协作约定
- API 前缀统一为 `/api/v1`。
- 管理员后台接口统一放在 `/api/v1/admin/*`。
- 响应格式统一为 `code`、`message`、`data`。
- 列表接口统一支持分页、筛选、排序。
- 路由守卫按角色控制页面权限，用户端与后台接口令牌独立校验。
- 页面静态复现阶段的模拟数据统一放在 `src/mocks/`，避免在页面组件中散写大段假数据。
